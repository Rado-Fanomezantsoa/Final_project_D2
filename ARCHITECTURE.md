# PROJECT DONNEES 2 - DataPulse

## Description

An automated ETL pipeline that collects air quality data every 15 minutes from public APIs, transforms it into a clean and standardized dataset, stores it in a dimensional data warehouse, and provides dashboards for air quality analysis.

## Data Coverage

- **Cities:** 5
- **Collection frequency:** Every 15 minutes (live pipeline)
- **Backfill period:** 4 months of historical data (April 1 – July 1)
- **Timezone:** UTC

### Backfill Data (April 1 – July 1)

The data covering this period was generated by the `backfill.yml` workflow rather than the live pipeline. It provides one file per city, per month, allowing historical AQI trends to be reconstructed before the live collection started.

### Live Pipeline Data (July 27 – August 1)

Data from this period onward was generated by the live `main.yml` pipeline (the hourly/15-minute scheduled collection described below), rather than the backfill process.

- **July 27 – 30:** collection does not strictly respect the "once per hour" cadence. This is due to technical limitations of the GitHub Actions scheduler, which does not guarantee exact execution times for `schedule`-triggered workflows (delays and occasional skipped runs under platform load).
- **July 31 – August 1:** this issue is resolved. Runs are triggered externally via **cron-job.org**, configured by Eric, which calls the GitHub Actions API on a strict hourly schedule. As a result, the workflow runs for these two days appear in the GitHub Actions history as manually triggered (`workflow_dispatch`), which is expected and confirms that the cron-job.org setup is working as intended.

## Orchestration & Automation

Two separate GitHub Actions workflows handle the pipeline's execution:

### 1. Hourly AQI Pipeline (`main.yml`)
- **Trigger**: GitHub-native `schedule` (`*/15 * * * *`) + `workflow_dispatch`
- **Role**: extracts, cleans, and loads AQI data continuously on `main`
- **Known limitation**: GitHub Actions scheduled triggers only run on the repository's default branch (`main`). This occasionally causes merge conflicts on auto-generated files (`raw/`, `clean/final.csv`) when syncing feature branches with `main`.
- **Dedicated branch run**: to also run this pipeline hourly on a separate, isolated branch (`pipeline-hourly`) without waiting for a merge to `main`, execution is additionally triggered by an **external cron service** ([cron-job.org](https://cron-job.org)) calling the GitHub API:

  POST https://api.github.com/repos/Rado-Fanomezantsoa/Final_project_D2/actions/workflows/main.yml/dispatches
  Body: {"ref": "main"}

  Frequency: every hour (`0 * * * *`)

  Starting July 31, this same external trigger is also used to guarantee the strict hourly cadence on `main`, which is why runs from July 31 onward appear as manually triggered (`workflow_dispatch`) rather than as native `schedule` runs.
